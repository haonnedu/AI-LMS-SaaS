# FE-01: mock auth handoff

Owner: Duc. Proposed reviewer: Hao. Branch: `fe-01-auth-mock`.

The login page uses an in-memory mock adapter. It does not authenticate users,
authorize API access, create cookies, or protect preview routes. Reload clears
the sample session. No provider or backend contract has been selected here.

## FE-02a compatibility update

Successful mock login now navigates to `/onboarding`, not directly to `/`.
The five-second expiry timer still starts at successful login. For dashboard/menu
regression checks, first open the sample workspace, or use the preview link to
visit the dashboard without one. The historical verification records below
describe the earlier FE-01 behavior; use [FE-02a.md](FE-02a.md) for current flow.

Production always uses the successful mock scenario and omits the development
scenario selector. The demo notice remains visible in production.

## Adapter boundary

`AuthAdapter` exposes asynchronous `getSession`, `signIn`, and `signOut` methods.
`AuthSession` contains only a sample user ID and name. `AuthProvider` owns React
session state, submission exclusion, navigation, and the development expiry timer.
A future real adapter must separately address provider/session security and the
agreed backend contract; this mock is not an authorization mechanism.

## Follow-up: cancellation, timer and menu verification — 2026-10-22

Changes are local on `fe-01-auth-mock`. No backend/API/adapter contract,
dependencies, provider, or protected-route changes are included.

- Login cleanup invalidates pending work on unmount. The preview link cancels
  immediately on client navigation. Operation IDs guard both asynchronous steps,
  error handling, and `finally`; an older request cannot create a session or
  unlock/reset a newer request.
- Successful login clears the pending marker before navigation, preserving its
  session when the login screen unmounts.
- Sign-out clears the expiry timer and advances the operation ID. Expiry checks
  the session's operation ID before clearing identity or navigating.
- Menu state belongs to its current pathname. Expiry closes the menu across
  routes; scroll lock and keyboard listeners are cleaned up by the old effect.

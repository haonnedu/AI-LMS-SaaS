# FE-01: mock auth handoff

Owner: Duc. Proposed reviewer: Hao. Branch: `fe-01-auth-mock`.

The login page uses an in-memory mock adapter. It does not authenticate users,
authorize API access, create cookies, or protect preview routes. Reload clears
the sample session. No provider or backend contract has been selected here.

## Try it

Run `npm run dev`, then open `/login`. Select a development scenario before
clicking **Đăng nhập thử**:

| Scenario | Expected behavior |
|---|---|
| Thành công | Loading disables submission; navigate to `/` with Minh Anh (mẫu) in the sidebar. |
| Lỗi đăng nhập | Remain on login, announce error, allow retry. |
| Callback bị hủy | Remain on login, explain cancellation, allow retry. |
| Hết hạn sau 5 giây | Sign in, then clear sample user and return to login with an expiry notice. |

**Đăng xuất thử** clears the sample session and returns to login. On mobile,
open the sidebar to find the button. Reload while signed in: the sidebar returns
to **Khám phá Eduvia**, and preview pages remain accessible.

Production always uses the successful mock scenario and omits the development
scenario selector. The demo notice remains visible in production.

## Adapter boundary

`AuthAdapter` exposes asynchronous `getSession`, `signIn`, and `signOut` methods.
`AuthSession` contains only a sample user ID and name. `AuthProvider` owns React
session state, submission exclusion, navigation, and the development expiry timer.
A future real adapter must separately address provider/session security and the
agreed backend contract; this mock is not an authorization mechanism.
